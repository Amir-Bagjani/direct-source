# زبان نمایشی رابط MVP

وضعیت: تأییدشده

## تاریخ و زمان

- تاریخ و ساعت در رابط کاربری با تقویم شمسی و منطقهٔ زمانی تهران نمایش داده می‌شوند.
- ورودی‌های تاریخ بدون ساعت نیز برای کاربر شمسی‌اند؛ تبدیل به تاریخ میلادی پیش از ارسال یا در مرز API انجام می‌شود.
- شمارش مهلت سفارش، پرداخت، تحویل یا مغایرت از timestamp دقیق انجام می‌شود و متن یا تاریخ نمایشی مبنای محاسبه نیست.

## اصل

رابط وب باید تجربهٔ عادی و واقعی محصول را نمایش دهد. ماهیت شبیه‌سازی‌شدهٔ پرداخت‌ها و عملیات فقط در کد، داده و مستندات داخلی نگهداری می‌شود و در متن رابط دیده نمی‌شود.

همین قاعده برای پیامک کد تحویل نیز برقرار است: در MVP ارسال واقعی پیامک انجام نمی‌شود، اما رابط کاربر فقط عبارت‌های عادی «ارسال کد تحویل»، «کد ارسال شد» و «تأیید تحویل» را نمایش می‌دهد و نباید از «پیامک آزمایشی»، «کد تست» یا «پیامک شبیه‌سازی‌شده» استفاده کند.

همین قاعده برای تعرفهٔ آزمایشی حمل برقرار است: خرده‌فروش فقط «هزینهٔ حمل» و جزئیات محاسبه را می‌بیند. رابط نباید این مبلغ را «فیک» یا «تستی» بنامد و تا پیش از اتصال یا قرارداد واقعی نباید آن را تعرفهٔ رسمی یا استعلام زندهٔ یک شرکت حمل معرفی کند.

## واژه‌های نمایشی

| مفهوم داخلی | متن قابل‌نمایش در وب‌سایت |
|---|---|
| پرداخت شبیه‌سازی‌شده در انتظار اقدام | در انتظار پرداخت |
| اجرای پرداخت شبیه‌سازی‌شده | تأیید و پرداخت |
| پرداخت شبیه‌سازی‌شدهٔ موفق | پرداخت‌شده |
| تسویهٔ شبیه‌سازی‌شده | تسویه‌شده |
| سفارش آزمایشی | سفارش |
| صورتحساب آزمایشی | صورتحساب سفارش |
| تعرفهٔ آزمایشی حمل | هزینهٔ حمل |

## واژه‌های ممنوع در رابط

- آزمایشی
- شبیه‌سازی‌شده
- دمو
- تست
- Sandbox
- پرداخت صوری
- قیمت فیک
- تعرفهٔ تستی

## ادعاهای ممنوع

- نمایش شمارهٔ پیگیری بانکی بدون تراکنش واقعی
- نمایش نام یک درگاه یا بانک بدون اتصال واقعی
- معرفی صورتحساب سفارش به‌عنوان فاکتور رسمی یا صورتحساب مالیاتی
- ادعای برداشت، واریز یا بازگشت واقعی وجه
- انتساب هزینهٔ حمل به تعرفهٔ رسمی یا استعلام زندهٔ یک شرکت بدون اتصال یا قرارداد واقعی

## الزام داخلی

هر رویداد مالی باید نوع اجرای خود را در داده نگه دارد تا سوابق MVP بعداً با تراکنش‌های واقعی اشتباه نشوند. حذف واژه‌های آزمایشی از رابط نباید این تمایز داخلی را از بین ببرد.
