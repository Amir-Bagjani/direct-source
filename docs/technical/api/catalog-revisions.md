# بازنگری محتوا و نمایش قیمت عمده

تحویل 2026-09-09؛ همهٔ endpointهای بازنگری Bearer می‌خواهند. محتوا از قیمت، عرضه و اتصال حمل جداست.

## بازنگری محصول

| مسیر زیر `/api/v1/catalog/` | عملیات |
|---|---|
| products/{id}/revisions/ | POST مالک تولیدکننده؛ ساخت draft برای محصول قبلاً منتشرشده |
| revisions/{id}/ | GET برای مالک محصول، مسئول یا مالک سامانه؛ PUT مالک برای draft/changes_requested |
| revisions/{id}/submit/ | POST مالک؛ ارسال برای بررسی و قفل نسخه |
| revision-queue/ | GET اپراتور؛ فهرست حداقلی صفحه‌بندی‌شده |
| revisions/{id}/claim/ | POST اپراتور؛ مسئولیت انحصاری |
| revisions/{id}/reassign/ | POST مالک سامانه؛ واگذاری pending به مسئول فعال با reason |
| revisions/{id}/review/ | POST فقط مسئول؛ approved/changes_requested/rejected به همراه code و reason |
| revisions/{id}/cancel/ | POST مالک؛ reason لازم؛ لغو نسخهٔ باز بدون تغییر نسخهٔ عمومی |

مثال ایجاد یا اصلاح:

```json
{"profile":{"name":"نام جدید","description":"توضیحات جدید"}}
```

profile ویرایش جزئی category/name/description/brand/manufacturer_model/attributes/images است. بخش ارسال‌نشده از آخرین پیشنهاد حفظ می‌شود. attributes و images در صورت ارسال کامل جایگزین می‌شوند. هیچ فیلد مالی یا عرضه از profile پذیرفته و اعمال نمی‌شود.

variants اختیاری است، اما در صورت ارسال **فهرست کامل تنوع‌های موردنظر** است:

```json
{
  "variants":[
    {"id":"EXISTING_VARIANT_UUID","sku":"CURRENT-SKU","attributes":{"color":"black"},"images":[]},
    {"sku":"NEW-SKU","attributes":{"color":"white"},"images":[],
     "supply":{"mode":"ready","ready_stock":20,"production_cap":0,"lead_time_days":0},
     "package":{"weight_g":500,"length_mm":200,"width_mm":100,"height_mm":80,"package_count":1}}
  ]
}
```

تنوع موجود id دارد و supply/package آن از این مسیر تغییر نمی‌کند. تنوع تازه بدون id ارسال می‌شود؛ سرور UUID پایدار را در proposed برمی‌گرداند و در ویرایش همان پیشنهاد می‌توان همان UUID را استفاده کرد. supply و package تنوع تازه الزامی‌اند؛ قیمت آن از پیش‌فرض **جاری** پله‌ها به ارث می‌رسد و پس از پذیرش می‌توان override مستقل ثبت کرد.

تنوع حذف‌شده از فهرست، هنگام تأیید is_active=false می‌شود؛ ردیف و SKU و ارجاع‌هایش باقی می‌مانند. SKU بایگانی‌شده قابل استفادهٔ مجدد نیست. قید ترکیب ویژگی فقط روی تنوع‌های فعال اعمال می‌شود. بستهٔ دارای تنوع بایگانی‌شده از جدول قابل‌انتخاب حذف و quote آن رد می‌شود. اگر این حذف حداقل شروع قیمت یا روش فروش را نامعتبر کند، بازنگری پذیرفته نمی‌شود؛ ابتدا برنامهٔ فروش جاری را اصلاح کنید. فهرست خصوصی تنوع‌ها is_active را نشان می‌دهد؛ نمای عمومی فقط فعال‌ها را برمی‌گرداند.

قواعد ویژگی، فایل، SKU، عرضه، بسته و انتشار در ذخیره/ارسال/پذیرش بازبینی می‌شوند. ذخیرهٔ draft نیز باید یک پیشنهاد کامل و معتبر بسازد؛ draft به معنی عدم ارسال برای اپراتور است. برای استفادهٔ مجدد از منطق واقعی، اعتبارسنجی ذخیره و ارسال در savepoint برگشت‌خورده انجام می‌شود؛ هیچ محصول یا تنوع تازه‌ای بیرون از تراکنش دیده نمی‌شود و هیچ پیام یا فایل خارجی ساخته نمی‌شود.

## حفظ نسخهٔ عمومی و عملیات جدیدتر

before محتوای مصوب هنگام ایجاد و proposed پیشنهاد مستقل است. فقط یک نسخه در draft/pending/changes_requested باز می‌ماند؛ قید جزئی PostgreSQL و قفل محصول این را کنترل می‌کنند. نسخهٔ pending قابل‌ویرایش نیست. approved/rejected/cancelled با trigger دیتابیس تغییرناپذیرند.

پذیرش فقط محتوا و تنوع‌های تازه/حذف‌شده را اتمیک اعمال می‌کند. قیمت، موجودی و بستهٔ تنوع موجود و اتصال حمل از snapshot قدیمی بازنویسی نمی‌شوند. اگر تغییر عملیاتی جدید، عرضه یا پوشش را نامعتبر کرده باشد، پذیرش رد می‌شود و تغییر محتوا rollback می‌شود. محصول inactive با پذیرش بازنگری خودکار فعال نمی‌شود. تصمیم‌ها audit و اعلان outbox دارند.

اپراتور مسئول می‌تواند لینک تصاویر ارجاع‌شده در before و proposed همان بازنگری pending را بگیرد؛ این مجوز دسترسی به مدارک هویتی نمی‌دهد.

## قیمت در API عمومی

در GET مسیرهای `public/products/` و `public/products/{id}/` احراز هویت Bearer اختیاری است. پاسخ همواره محتوای عمومی و تنوع‌های فعال را دارد. فقط مالک یک Business خرده‌فروشی verified با حساب فعال و غیرمعلق، فیلد `wholesale` دریافت می‌کند؛ این فیلد همان جدول برنامهٔ فروش/پله‌ها/effective_prices با واحد IRR است.

مهمان، تولیدکننده، خرده‌فروش تأییدنشده/معلق و کاربر صرفاً واردشده به Django Admin، **کل فیلد wholesale را دریافت نمی‌کنند**. مجوز خرید controlled_access شرط دیدن قیمت نیست. پاسخ Cache-Control: no-store دارد. JWT نامعتبر طبق قرارداد احراز هویت رد می‌شود؛ session ادمین جای Bearer نیست.

مرتب‌سازی و فیلتر قیمت، جست‌وجوی کاتالوگ، وضعیت مستقل تنوع و بازتخصیص صف در [قرارداد تکمیلی](catalog-browsing-lifecycle.md) پیاده شده‌اند. سبد/سفارش متعلق به PRD-04 است.

## اجرای نسخهٔ جدید

migrationهای catalog تا 0006 همراه کد جدید لازم‌اند. بک‌اند روشن از image قبلی استفاده می‌کند؛ برای به‌روزرسانی کد و schema، launcher فعلی را با Ctrl+C ببندید و دوباره `./run-backend.sh` را اجرا کنید. migration جدید به‌تنهایی روی image قدیمی اعمال نشود؛ Variant و TaxonomyProposal schema تازه دارند.
