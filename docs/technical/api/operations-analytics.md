# API عملیات و آمار — PRD-08

این برش فقط بک‌اند است. رابط عملیات و داشبوردها بعداً با Next.js ساخته می‌شوند؛ مسیر HTML یا فرم Django برای عملیات وجود ندارد. احراز هویت، قالب خطا و pagination مطابق قرارداد مشترک API هستند.

## صف و اقدامات

پیشوند تمام مسیرهای زیر `/api/v1/operations/` است.

| روش و مسیر | کاربرد و مجوز |
| --- | --- |
| `GET work/` | صف جاری PostgreSQL؛ مالک و اپراتور |
| `POST work/{kind}/{id}/claim/` | پذیرش اتمیک مسئولیت؛ `reason` الزامی |
| `POST work/{kind}/{id}/command/` | فرمان دامنه با `command`، `reason`، `idempotency_key` و `parameters` |
| `GET work/{kind}/{id}/timeline/` | جزئیات و تاریخچه؛ مسئول پرونده یا مالک |
| `POST suspensions/` | پیشنهاد تعلیق با دقیقاً یکی از `business_id` یا `user_id`، دلیل و حداکثر ده مدرک مجاز |
| `GET/POST policy/` | مشاهده یا ثبت نسخهٔ مهلت‌ها؛ فقط مالک |
| `GET policy/history/` | تاریخچهٔ نسخه‌های مهلت و تنظیمات تحویل؛ فقط مالک |
| `GET dashboard/` | شاخص‌های مجاز نقش و کسب‌وکار |
| `GET dashboard/{metric}/` | کارت شاخص و رکوردهای سازندهٔ صفحه‌بندی‌شده |

نوع صف: `business`، `product`، `tariff`، `order`، `shipping`، `delivery`، `dispute`، `ticket`، `review`، `suspension` و `disposition`. شناسهٔ صف کسب‌وکار، شناسهٔ VerificationApplication است. تصمیم‌های سفارش تعلیق‌شده زیرصف مستقل دارند.

فیلتر صف شامل `start`، `end`، `status`، `kind`، `assignee` و `sort=oldest|newest` است؛ `assignee=unassigned` کارهای بدون مسئول را برمی‌گرداند. ردیف‌ها نوع، علت، وضعیت، مسئول، زمان ایجاد/تغییر، عمر به ثانیه و فرمان‌های مجاز نقش را دارند. پیش‌شرط نهایی فرمان در سرویس دامنه بررسی می‌شود.

در claim هم‌زمان فقط یک درخواست موفق می‌شود و دیگری `409` می‌گیرد. مالک با `user_id` و دلیل می‌تواند مسئول را تغییر دهد. غیرفعال‌کردن اپراتور، مسئولیت‌ها را اتمیک آزاد می‌کند. APIهای دامنه‌ای موجود در اولین اقدام مجاز، کار بدون مسئول را اتمیک به اجراکننده تخصیص می‌دهند؛ اقدام اپراتور دیگر روی کار واگذارشده رد می‌شود.

فرمان‌ها allowlist دارند؛ تغییر دلخواه status، مبلغ، snapshot یا deadline پذیرفته نمی‌شود. تکرار همان کلید و payload نتیجهٔ قبلی را برمی‌گرداند؛ تغییر payload با همان کلید `409` است. کنترل نقش پیش از بازگرداندن نتیجهٔ قبلی انجام می‌شود. بازگشایی تیکت بسته فرمان اختصاصی مالک با دلیل است.

## تعلیق و تنظیمات

اپراتور پیشنهاد تعلیق ثبت می‌کند؛ فعال‌سازی، رد و بازگردانی فقط با فرمان مالک انجام می‌شوند. تعلیق User ورود و نشست‌های او را مسدود می‌کند و وضعیت Business را تغییر نمی‌دهد. تعلیق Business مانع فعالیت جدید است. سفارش پرداخت‌نشده لغو و رزرو آزاد می‌شود؛ سفارش پرداخت‌شده، disposition و توقف تسویهٔ مستقل می‌گیرد. مالک برای هر سفارش `continue` یا، پیش از ارسال، `cancel_refund` ثبت می‌کند. سفارش ارسال‌شده قابل لغو از این مسیر نیست. بازگردانی حساب، سفارش لغوشده یا تصمیم نهایی قبلی را بازنویسی نمی‌کند و توقف‌های تعیین‌تکلیف‌نشده باقی می‌مانند.

تنظیم مهلت‌ها: `order_hours`، `payment_hours`، `cancellation_hours`، `discrepancy_hours`، `discrepancy_response_hours` و `review_days`. `effective_at` اختیاری و ISO-8601 است؛ نسخهٔ آینده پیش از زمان اثر استفاده نمی‌شود. deadlineهای ساخته‌شده بازنویسی نمی‌شوند. نرخ کارمزد از API مالی و تنظیمات کد تحویل از API لجستیک تغییر می‌کنند. نسخهٔ کارمزد در CommissionRate، نسخهٔ مهلت و تحویل در PolicyVersion و رد تغییر در AuditEvent نگهداری می‌شود. TTL و تعداد تلاش هر challenge هنگام صدور snapshot می‌شوند.

Audit شامل actor، نقش، فرمان/منبع، موجودیت، زمان UTC، دلیل، before/after و correlation است. تاریخچه، نتیجهٔ فرمان و تصمیم نهایی سفارش در PostgreSQL در برابر تغییر/حذف محافظت می‌شوند. secretها، tokenها و URLهای امضاشده از audit حذف محتوایی می‌شوند.

## تعریف آمار و دسترسی

داده زنده است؛ `cached=false` و `updated_at` زمان تولید پاسخ را مشخص می‌کنند. بازهٔ پیش‌فرض ۳۰ روز و حداکثر ۳۶۶ روز است: `start` شامل و `end` غیرشامل. زمان‌ها ISO-8601 و مبالغ ریال‌اند. تبدیل تاریخ شمسی و نمایش تهران مسئولیت Next.js است.

فیلتر تاریخ بر `created_at` رکورد سازنده اعمال می‌شود: برای فروش و خرید، رویداد تسویه؛ برای پرداخت، رویداد پرداخت؛ برای آماده‌سازی و حمل، رکورد درخواست/مرسوله. `status` برای معیارهای وابسته به سفارش، وضعیت فعلی Order و برای Business، Product، Ticket و Suspension وضعیت همان موجودیت است. کارت و drill-down از یک projection و فیلتر یکسان استفاده می‌کنند. برای بیش از ۵۰۰۰ رکورد منبع در هر شاخص/نوع صف، پاسخ خطای محدودکردن بازه داده می‌شود؛ خروجی بی‌صدا ناقص نمی‌شود.

فروش/خرید مبلغ نهایی کالای تسویه‌شده است؛ پرداخت به‌تنهایی فروش محسوب نمی‌شود. تعداد اقلام و رتبه‌بندی محصول/تنوع/تولیدکننده از تعداد نهایی retained در snapshot تسویه ساخته می‌شود. مبلغ منتظر تسویه، کالای باقی‌مانده منهای کارمزد تولیدکننده است. کارمزد رزروشده، کارمزد باقی‌ماندهٔ سفارش‌های فعالِ تسویه‌نشده؛ تعدیل‌شده از رویدادهای برگشتی و قطعی از تسویه محاسبه می‌شود. میانگین بدون داده `null` با `count=0` دارد؛ شمارش و جمع بدون داده صفر هستند.

مالک به شاخص‌های مالی کلان دسترسی دارد. درخواست مستقیم همان شاخص یا drill-down توسط اپراتور با `403` رد می‌شود. جزئیات مالی یک Order نیز برای اپراتور نیازمند پروندهٔ مرتبط واگذارشده است. Business فقط دادهٔ خود را می‌خواند؛ `business_id` برای کسب‌وکار دیگر مخصوص مالک است. نتایج مالی این MVP از رویدادهای `simulated` محاسبه می‌شوند.

نام‌ها، payloadها و مسیرهای کامل در [OpenAPI](openapi.yaml)؛ آزمون‌های پذیرش بک‌اند در [test_operations_analytics.py](../../../apps/backend/tests/test_operations_analytics.py) هستند.
