# قرارداد امتیاز و نظر — PRD-07

Backend: `marketplace.reviews`؛ مشخصات محصول: [PRD-07](../../product/prd/07-ratings-reviews.md). قرارداد ماشینی: [OpenAPI](openapi.yaml). مسیر پایه `/api/v1/reviews/`.

## ایجاد حق و تکمیل سفارش

`orders.complete_financial_cycle` در همان تراکنش تسویه، `reviews.create_entitlements(order_id=...)` را فراخوانی می‌کند. حق تنها برای Order دارای `completed_at`، تحویل کامل (`delivered_at` و `discrepancy_deadline`)، رویداد settlement معتبر و بدون پروندهٔ مغایرت باز ایجاد می‌شود. بدون پرونده، مهلت مغایرت نیز باید گذشته باشد. سفارش جبران‌شده‌ای که صرفاً اقلام باقی‌مانده‌اش تحویل شده و تحویل کامل ندارد، حق نمی‌گیرد.

برای هر محصول پایه یک حق از خرده‌فروش به تولیدکننده، و دو حق همکاری در جهت‌های مخالف ایجاد می‌شود. محصول و تنوع‌های واقعاً خریداری‌شده از OrderLine ثبت می‌شوند؛ نویسنده، دریافت‌کننده و موضوع ورودی کاربر نیستند. deadline مشترک برابر `completed_at + REVIEW_WINDOW_DAYS` است؛ پیش‌فرض ۱۴ روز. تنظیم تازه بر حق‌های موجود اثر ندارد. execution mode از settlement کپی می‌شود و تغییرناپذیر است. provider مالی فعلی فقط simulated می‌سازد؛ API هیچ مسیر ساخت یا تبدیل حق live ندارد.

Celery beat هر ۶۰ ثانیه `reviews.process_reviews` را اجرا می‌کند: سفارش‌های تکمیل‌شدهٔ فاقد حق را بازیابی می‌کند، نظر همکاری رسیده به deadline را منتشر و حق استفاده‌نشده را منقضی می‌کند. پیمایش با صفحات ۱۰۰۰تایی و continuation بر اساس PK است. انتشار می‌تواند تا نوبت بعدی worker عقب بیفتد، اما ارسال در timestamp دقیق deadline رد می‌شود. تمام تغییرات با قفل Order و در transaction انجام می‌شوند؛ اجرای تکراری حق یا انتشار تازه نمی‌سازد.

## مسیرها

| روش و مسیر | دسترسی و نتیجه |
| --- | --- |
| GET `entitlements/` | حق‌های خود Business نویسنده، صفحه‌بندی‌شده؛ هیچ حق یا وضعیت ارسال طرف مقابل برنمی‌گردد |
| GET `entitlements/{id}/` | حق خود، deadline و پیش‌نویس/نظر ارسال‌شدهٔ خود |
| PUT `entitlements/{id}/` | ذخیرهٔ کامل پیش‌نویس یا ارسال نهایی با `submit=true` |
| POST `entitlements/{id}/images/` | آپلود یک تصویر متعلق به حق محصول؛ multipart شامل `file` و `consent_version` |
| GET `public/`، `public/{review}/`، `public/aggregate/` | بدون نیاز به ورود؛ فقط live منتشرشده و معتبر |
| GET `internal/`، `internal/{review}/`، `internal/aggregate/` | فقط simulated منتشرشده؛ طرف مرتبط verified دارای controlled_access یا اپراتور/مالک فعال |
| GET `public/{review}/images/{file}/` و `internal/{review}/images/{file}/` | URL خصوصی کوتاه‌عمر، فقط با همان قواعد نمایش نظر و برای تصویر انتخاب‌شدهٔ آن |
| GET/PUT `{review}/reply/` | خواندن/ذخیرهٔ پاسخ خود Business دریافت‌کننده؛ PUT با `submit=true` نهایی می‌کند |
| POST `{review}/reports/` | گزارش نظر قابل‌مشاهده با `reason` و `reply_id` اختیاری برای گزارش پاسخ نهایی |
| GET `reports/` | صف صفحه‌بندی‌شدهٔ گزارش‌های حل‌نشده؛ فقط اپراتور/مالک فعال |
| POST `reports/{report}/moderation/` | اقدام مستدل اپراتور/مالک با کلید تکرارپذیری |
| GET `{review}/audit/` | هویت داخلی نویسنده، اصل نظر/پاسخ و تاریخچه؛ فقط اپراتور/مالک، همراه ثبت دسترسی |

فهرست‌ها از `page` و `page_size` استفاده می‌کنند. فهرست نظر و aggregate فیلترهای `product`، `business` (دریافت‌کننده) و `topic` دارند. ورودی ناشناخته رد می‌شود؛ پارامتر تغییر execution mode وجود ندارد. نبود دسترسی به نظر کور/غیرمرتبط و فایل، ۴۰۴ برمی‌گرداند؛ پایان مهلت و تلاش برای تغییر محتوای نهایی ۴۰۹، دادهٔ نامعتبر ۴۰۰، و نقش غیرمجاز ۴۰۳ است. حذف و بازگرداندن محتوای نهایی به پیش‌نویس endpoint ندارد.

## امتیاز و پیش‌نویس

بدنهٔ PUT حق:

```json
{
  "scores": {"quality": 5, "conformity": 4, "overall": 5},
  "text": "کیفیت مطابق انتظار بود",
  "images": [],
  "submit": true
}
```

| topic | نویسنده → دریافت‌کننده | معیارهای لازم |
| --- | --- | --- |
| product | خرده‌فروش → تولیدکننده | quality، conformity، overall |
| manufacturer | خرده‌فروش → تولیدکننده | packaging، timeliness، communication، overall |
| retailer | تولیدکننده → خرده‌فروش | communication، coordination، overall |

امتیازها عدد صحیح ۱ تا ۵ هستند؛ bool، رشته و اعشار پذیرفته نمی‌شوند. پیش‌نویس می‌تواند معیارهای ناقص داشته باشد؛ ارسال تمام معیارهای موضوع را می‌خواهد. PUT جایگزینی کامل پیش‌نویس است؛ متن و images حذف‌شده از payload خالی می‌شوند. متن حداکثر ۸۰۰۰ نویسه و تصویر حداکثر ۱۰ فایل غیرتکراری است. فقط تصاویر JPEG/PNG/WebP حداکثر ۱۰ MiB که اسکن پاک، مالک درست و scope همان حق دارند قابل انتخاب‌اند. فایل در storage خصوصی با مسیر تصادفی بدون شناسهٔ Business ذخیره می‌شود.

ارسال محصول فوراً published می‌شود. همکاری تا ارسال هر دو طرف یا deadline مخفی است؛ ارسال دوم، هر دو ردیف را با timestamp یکسان اتمیک منتشر می‌کند. پیش از انتشار، حتی شمارش و endpoint گزارش/پاسخ وجود نظر طرف مقابل را افشا نمی‌کنند. مشاهدهٔ داخلی کامل برای حسابرسی نقش پلتفرم، endpoint مجزا دارد. پس از ارسال، متن/نمرات/images/actor و زمان ارسال با trigger PostgreSQL قفل‌اند؛ رابطهٔ پاسخ، موضوع، deadline، execution mode و تنوع‌های حق نیز محافظت می‌شوند.

نظر محصول در projection منتشرشده فقط `author_label=خریدار تأییدشده` دارد؛ Order، entitlement، شناسه یا نام Business خرده‌فروش و مشخصات شخص در آن نیست. همکاری نام نمایشی Business نویسنده را نشان می‌دهد، نه هویت شخص. پیش‌نویس پاسخ در projection عمومی/طرف مقابل دیده نمی‌شود. پاسخ نهایی یک‌بار ثبت و immutable است.

## نظارت و تجمیع

بدنهٔ اقدام:

```json
{"action": "hide_content", "reason": "وجود اطلاعات شخصی در متن", "idempotency_key": "c74ab827-b4f3-4581-8236-939ba9a0b5f9"}
```

- `hide_content` و `unhide_content`: متن و تصاویر نظر یا متن پاسخ را مخفی/بازیابی می‌کند؛ امتیاز حفظ می‌شود.
- `invalidate` و `revalidate`: کل نظر را از نمایش و aggregate خارج/به آن بازمی‌گرداند؛ برای پاسخ مجاز نیست.
- `dismiss`: گزارش را بدون تغییر محتوا رد می‌کند.

دلیل اجباری است؛ اپراتور متن یا امتیاز را ویرایش نمی‌کند. گزارش یک actor برای یک نظر/پاسخ یکتاست. تکرار گزارش همان رکورد را برمی‌گرداند. هر اقدام ModerationAction با before/after و actor دارد و به audit عمومی زیرساخت هم نوشته می‌شود. تکرار همان کلید و payload نتیجهٔ قبلی را می‌دهد؛ payload متفاوت ۴۰۹ است. اصل داده و تاریخچه حذف نمی‌شوند. پنهان‌سازی جلوی صدور URL تازهٔ تصویر را می‌گیرد؛ URL امضاشدهٔ قبلی تا پایان TTL زیرساخت (۶۰ ثانیه) اعتبار دارد.

aggregate با AVG و COUNT PostgreSQL از منبع اصلی محاسبه می‌شود؛ snapshot یا counter قابل دوباره‌شماری ندارد. موضوع‌ها جدا هستند. هر معیار `mean` و `count` دارد؛ نبود نظر، `mean=null`، `count=0` و پیام «هنوز امتیازی ندارد» است. پیش‌نویس، نظر کور و نظر invalidated وارد میانگین نمی‌شوند. دادهٔ simulated هرگز در public نیست؛ aggregate داخلی کاربر فقط سفارش‌های قابل‌مشاهدهٔ خودش و aggregate اپراتور کل دادهٔ simulated را پوشش می‌دهد.

## اتصال به پشتیبانی و مرز تحویل

در PRD-06 دستهٔ `reviews` و پیوندهای `related_type=review/reply` اضافه شده‌اند. نویسنده می‌تواند بابت نظر خود تیکت بزند؛ دیگران فقط بابت محتوای مجاز برای مشاهده. پیوند یک نظر عمومی برای شخص ثالث حق مشاهدهٔ Order نمی‌سازد. نظر، گزارش، پاسخ، تیکت محتوا و moderation هیچ دستور تغییر مالی، مغایرت یا وضعیت سفارش اجرا نمی‌کنند.

پنل وب مدیریت، ثبت/پاسخ/گزارش نظر در وب و داشبوردهای PRD-08 در این قرارداد تحویل frontend نشده‌اند.

### نمایش فقط‌خواندنی در جزئیات محصول — PRD-02

صفحهٔ محصول وب فهرست عمومی همین قرارداد را با `topic=product`، شناسهٔ همان محصول و
`page_size=5` می‌خواند. BFF مسیر `GET /api/bff/catalog/products/{id}/reviews?page=N`
فقط صفحهٔ صحیح مثبت تا هفت رقم را می‌پذیرد؛ topic، Business و execution mode ورودی وب
نیستند. درخواست upstream بدون cookie یا authorization و پاسخ `no-store` است. UI وضعیت
دریافت، خالی، خطا/تلاش دوباره و صفحه‌بندی را مستقل از محتوای اصلی محصول نمایش می‌دهد.
عنوان نویسندهٔ محصول از پیام محلی «خریدار تأییدشده» است؛ نام/شناسهٔ شخص یا Business
خریدار نمایش داده نمی‌شود. سه معیار، تاریخ انتشار و پاسخ نهایی موجود نمایش داده می‌شوند.
`content_hidden` در UI نیز متن و تصویر نظر/متن پاسخ را می‌پوشاند؛ امتیاز حفظ می‌شود.

تصویرها فقط پس از اقدام «نمایش تصاویر نظر» درخواست می‌شوند. BFF
`GET /api/bff/catalog/reviews/{review}/images` ابتدا نظر را مجدداً از public می‌خواند،
سپس برای حداکثر ده فایل انتخاب‌شدهٔ آن، مسیر public image موجود را موازی فراخوانی می‌کند.
اگر محتوا پنهان باشد فایل خوانده نمی‌شود؛ حذف دسترسی/نامعتبرشدن نظر یا شکست لینک، خطای
قابل تلاش دوباره می‌دهد. URLها در Query مجزای بدون نگهداری پس از unmount هستند و
محدودیت TTL شصت‌ثانیه‌ای زیرساخت همچنان برقرار است. این مسیر مجوز داخلی یا simulated
را استفاده نمی‌کند و امکان نوشتن نظر، پاسخ یا گزارش ایجاد نمی‌کند.

تست مثبت UI با projection قراردادی در component و BFF انجام می‌شود؛ محیط مرورگر واقعی
با provider مالی simulated فقط حالت عمومی خالی را اثبات می‌کند. دادهٔ simulated برای
پرکردن نمونهٔ عمومی یا ادعای تست end-to-end مثبت live تبدیل نشده است.
