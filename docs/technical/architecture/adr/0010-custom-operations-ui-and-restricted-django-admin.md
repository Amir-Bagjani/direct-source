# ADR-0010: پنل سفارشی عملیات و Django Admin محدود

## وضعیت

Accepted

## تاریخ

2026-09-03

## زمینه و مسئله

اپراتورهای پلتفرم برای بررسی کسب‌وکار و محصول، لجستیک، سفارش، مغایرت و پشتیبانی به صف و گردش کاری روزانه نیاز دارند. Django Admin ویرایش مستقیم رکورد را ساده می‌کند، اما چنین ویرایشی می‌تواند validation دامنه، transitionهای مجاز، تفکیک دسترسی و حسابرسی اقدامات حساس را دور بزند.

## محرک‌های تصمیم

- اجرای همهٔ transitionهای تجاری از service/command معتبر
- دسترسی حداقلی اپراتورها و جلوگیری از دسترسی مستقیم به مدل‌ها
- ثبت actor، دلیل و مقدار قبل/بعد برای اقدامات حساس
- رابط صف‌محور متناسب با کار روزانهٔ اپراتور
- حفظ ابزار سادهٔ داخلی برای تنظیمات کم‌ریسک و عیب‌یابی مالک سامانه

## گزینه‌های بررسی‌شده

### پنل سفارشی عملیات همراه Django Admin محدود

- مزایا: گردش‌های امن و متناسب برای اپراتور، حسابرسی قابل‌کنترل و حفظ ابزار داخلی کم‌هزینه برای مالک
- معایب: ساخت و نگهداری رابط سفارشی و دو سطح ابزار داخلی

### استفاده از Django Admin برای همهٔ عملیات

- مزایا: توسعهٔ سریع و امکانات آمادهٔ CRUD
- معایب: ریسک دورزدن قواعد دامنه، تجربهٔ ضعیف برای صف‌های کاری و دشواری محدودسازی تغییرات حساس

### حذف کامل Django Admin

- مزایا: یک مسیر واحد برای تمام عملیات
- معایب: هزینهٔ اضافی برای ساخت ابزارهای کم‌ریسک، مشاهده و عیب‌یابی داخلی

## تصمیم

کارهای روزانهٔ اپراتورها فقط در پنل سفارشی عملیات و از طریق API و service/commandهای دامنه انجام می‌شوند. اپراتور پلتفرم به Django Admin دسترسی ندارد.

Django Admin فقط برای مالک سامانه و کاربران فنی صریحاً مجاز، برای مشاهده، عیب‌یابی و تنظیمات کم‌ریسک استفاده می‌شود. تغییر مستقیم وضعیت سفارش و گردش‌ها، مبالغ، کارمزد، بازپرداخت، تسویه و سایر داده‌های حساس از Django Admin ممنوع است؛ این اقدامات حتی برای مالک باید از command حسابرسی‌شدهٔ پنل عملیات عبور کنند.

## دلیل

پنل سفارشی می‌تواند دسترسی، پیش‌شرط، دلیل اجباری و اثرات جانبی هر اقدام را به‌صورت دامنه‌ای اعمال کند. نگه‌داشتن Django Admin محدود نیز سرعت ساخت ابزارهای مشاهده و تنظیمات ساده را حفظ می‌کند، بدون آنکه به مسیر موازی تغییر داده تبدیل شود.

## پیامدها

### مثبت

- اپراتورها راهی برای ویرایش مستقیم رکورد یا دورزدن گردش‌ها ندارند.
- صف‌ها، خطاها و اقدام‌های مجاز متناسب با وظیفهٔ هر نقش نمایش داده می‌شوند.
- حسابرسی اقدامات حساس در یک مسیر واحد باقی می‌ماند.

### منفی و ریسک‌ها

- بخشی از پنل سفارشی باید پیش از انجام عملیات روزانه آماده شود.
- ثبت اشتباه model در Django Admin می‌تواند سطح دسترسی ناخواسته ایجاد کند.
- مجوز بسیار گستردهٔ مالک یا حساب فنی همچنان ریسک سوءاستفاده دارد.

### اقدامات لازم

- Django Admin با allowlist مدل/فیلد ساخته شود و مدل‌های حساس ثبت نشوند یا کاملاً read-only باشند.
- دسترسی Django Admin برای اپراتور رد و برای حساب‌های مجاز با آزمون permission کنترل شود.
- تمام mutationهای پنل عملیات از API و commandهای audit‌شده با reason و before/after عبور کنند.
- دسترسی مالک و حساب فنی ثبت، بازبینی دوره‌ای و با احراز هویت قوی محافظت شود.
