# ADR-0011: ذخیرهٔ پول به ریال و نمایش به تومان

## وضعیت

Accepted

## تاریخ

2026-09-03

## زمینه و مسئله

کاربران ایرانی معمولاً قیمت را با تومان می‌خوانند و وارد می‌کنند، در حالی که واحد رسمی و مناسب قرارداد داده ریال است. مبهم‌بودن واحد یا تبدیل ضمنی می‌تواند قیمت، کارمزد، هزینهٔ حمل، بازپرداخت و تسویه را ده‌برابر اشتباه کند.

## محرک‌های تصمیم

- واحد یکتا و صریح در دیتابیس و API
- محاسبهٔ دقیق و بدون خطای اعشاری برای دادهٔ مالی
- رابط هماهنگ با انتظار کاربر ایرانی
- نام‌گذاری قابل‌ردیابی در schema و قرارداد API

## گزینه‌های بررسی‌شده

### ریال در داده و تومان در رابط

- مزایا: قرارداد رسمی و یکتا در backend، تجربهٔ آشنا در UI و تبدیل ثابت و دقیق
- معایب: نیاز به تبدیل صریح در مرز UI و خطر خطای ده‌برابری در صورت نقض قرارداد

### تومان در همهٔ لایه‌ها

- مزایا: نزدیک‌تر به زبان روزمرهٔ کاربر
- معایب: کد واحد رسمی استاندارد ندارد و یکپارچه‌سازی و گزارش رسمی را مبهم می‌کند

### مقدار اعشاری همراه واحد متغیر

- مزایا: انعطاف برای چند ارز و واحد
- معایب: پیچیدگی و امکان rounding و اختلاط واحد، بدون نیاز واقعی MVP

## تصمیم

تمام مبالغ در PostgreSQL و API به‌صورت عدد صحیح ریال ایران با کد `IRR` نگهداری و منتقل می‌شوند. نام فیلدهای مبلغ در API پسوند `_rial` دارد. رابط کاربری مبلغ را با برچسب صریح تومان دریافت و نمایش می‌دهد و در مرز رابط با تبدیل ثابت هر ۱ تومان به ۱۰ ریال تبدیل می‌کند.

مبلغ اعشاری و گردکردن مجاز نیست. snapshotهای مالی سفارش نیز مقدار ریالی را نگه می‌دارند.

## دلیل

عدد صحیح ریال یک قرارداد ساده، رسمی و بدون rounding برای همهٔ محاسبات مالی ایجاد می‌کند و تبدیل ثابت در رابط تجربهٔ رایج تومان را حفظ می‌کند.

## پیامدها

### مثبت

- جمع، تفریق، کارمزد و تطبیق مالی بدون خطای اعشاری انجام می‌شوند.
- واحد هر فیلد API از نام آن مشخص است.
- همهٔ دامنه‌ها از سفارش تا حمل و بازپرداخت قرارداد یکسان دارند.

### منفی و ریسک‌ها

- تبدیل دوباره یا فراموش‌شده در UI می‌تواند مبلغ را ده‌برابر کند.
- واردکردن مستقیم داده بدون رعایت واحد خطرناک است.

### اقدامات لازم

- component مشترک ورود/نمایش تومان و تبدیل تست‌شده استفاده شود.
- contract test مقدارها و پسوند `_rial` را کنترل کند.
- fixture، گزارش داخلی و دادهٔ seed واحد صریح داشته باشند.
- invariantهای جمع اقلام، هزینهٔ حمل، کارمزد و مبلغ نهایی با عدد صحیح آزموده شوند.
