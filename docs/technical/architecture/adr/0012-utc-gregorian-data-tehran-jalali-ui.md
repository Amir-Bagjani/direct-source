# ADR-0012: UTC و میلادی در داده، تهران و شمسی در رابط

## وضعیت

Accepted

## تاریخ

2026-09-03

## زمینه و مسئله

گردش‌های سفارش، تولید، حمل، مغایرت، کد تحویل و تسویه deadlineهای دقیق دارند. کاربران تاریخ شمسی و ساعت ایران را انتظار دارند، اما نگهداری زمان محلی یا تاریخ نمایشی در backend می‌تواند مقایسه، زمان‌بندی و یکپارچه‌سازی را مبهم کند.

## محرک‌های تصمیم

- مقایسه و زمان‌بندی یکنواخت در backend و worker
- حذف ابهام timezone از API و دیتابیس
- نمایش و ورود آشنا برای کاربر ایرانی
- قرارداد استاندارد برای Next.js و سامانه‌های آینده

## گزینه‌های بررسی‌شده

### UTC/میلادی در داده و تهران/شمسی در رابط

- مزایا: قرارداد استاندارد و قابل‌مقایسه در backend همراه تجربهٔ محلی در UI
- معایب: نیاز به تبدیل و تست مرزهای تقویم و timezone

### ساعت تهران و شمسی در همهٔ لایه‌ها

- مزایا: شباهت مستقیم داده به نمایش کاربر
- معایب: ناسازگاری با ابزارها، queryها و یکپارچه‌سازی‌ها و دشواری محاسبهٔ deadline

### timestamp بدون timezone

- مزایا: مدل ظاهراً ساده‌تر
- معایب: لحظهٔ واقعی رویداد مبهم و تبدیل میان محیط‌ها پرخطا می‌شود

## تصمیم

همهٔ timestampها در دیتابیس و API به‌صورت timezone-aware با UTC، تقویم میلادی و قالب ISO 8601 نگهداری و منتقل می‌شوند. رابط کاربری آن‌ها را با منطقهٔ زمانی تهران و تقویم شمسی نمایش می‌دهد و ورودی محلی را پیش از ارسال به قرارداد استاندارد تبدیل می‌کند.

تاریخ‌های بدون ساعت در داده به‌صورت تاریخ میلادی ذخیره می‌شوند. deadlineها همیشه timestamp مطلق‌اند و از متن یا تاریخ نمایشی محاسبه نمی‌شوند.

## دلیل

UTC و ISO 8601 برای محاسبات، API و worker یک مرجع یکتا فراهم می‌کنند؛ تبدیل صرفاً در مرز UI نیاز کاربر ایرانی را بدون آلوده‌کردن مدل دامنه برآورده می‌کند.

## پیامدها

### مثبت

- تمام سرویس‌ها و taskها یک لحظه را یکسان تفسیر می‌کنند.
- مقایسه، انقضا و حسابرسی رویدادها پایدار می‌شود.
- تغییر نحوهٔ نمایش تقویم روی دادهٔ ذخیره‌شده اثر ندارد.

### منفی و ریسک‌ها

- تبدیل نادرست تاریخ شمسی یا timezone می‌تواند deadline را جابه‌جا کند.
- date-only و timestamp باید در قرارداد API صریحاً از هم جدا باشند.

### اقدامات لازم

- timezone-aware بودن در تنظیمات Django اجباری و datetime ساده رد شود.
- contract test قالب ISO 8601 و UTC را کنترل کند.
- تبدیل شمسی/میلادی و مرز روز در ساعت تهران تست شود.
- Celery زمان و deadline جاری را از PostgreSQL بخواند و با UTC مقایسه کند.
