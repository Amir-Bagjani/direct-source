# سیاست آپلود فایل در MVP

وضعیت: `Accepted`

این سند محدودیت مشترک همهٔ endpointهای آپلود را مشخص می‌کند. اگر یک جریان محصولی محدودیت سخت‌گیرانه‌تری داشته باشد، همان محدودیت سخت‌گیرانه‌تر اعمال می‌شود.

## محدودیت‌ها

| نوع فایل | فرمت‌های مجاز | حداکثر حجم هر فایل |
| --- | --- | --- |
| تصویر محصول و تنوع | JPG، PNG، WebP | ۵ مگابایت |
| مدرک هویتی یا کسب‌وکار | JPG، PNG، WebP، PDF | ۱۰ مگابایت |
| مدرک مغایرت، حمل و پیوست پشتیبانی | JPG، PNG، WebP، PDF | ۱۰ مگابایت |

- در هر درخواست یا ارسال فرم حداکثر ۱۰ فایل پذیرفته می‌شود.
- محدودیت دامنه‌ای گالری محصول، تصویر تنوع یا فیلدهای اجباری مستقل است و می‌تواند کمتر از ۱۰ فایل باشد.
- فایل اجرایی، archive، سند اداری قابل‌ویرایش، SVG و هر فرمت خارج از allowlist رد می‌شود.

## اعتبارسنجی و امنیت

- اندازه، پسوند، MIME اعلام‌شده و امضای واقعی فایل باید سمت سرور بررسی شوند؛ نام یا header ارسالی کاربر قابل‌اعتماد نیست.
- محدودیت حجم و نوع در policy آپلود مستقیم object storage و هنگام نهایی‌سازی metadata هر دو اعمال می‌شود.
- فایل تا پایان validation و اسکن بدافزار production قابل‌نمایش یا دانلود نیست.
- کلید object توسط سیستم و غیرقابل‌حدس تولید می‌شود و نام فایل کاربر مسیر ذخیره‌سازی را تعیین نمی‌کند.
- فایل خصوصی است و فقط با authorization و URL امضاشدهٔ کوتاه‌عمر قابل‌دسترسی است.
- نگهداری و حذف از ADR-0006 پیروی می‌کند؛ ردشدن یا جایگزینی فایل باعث حذف خودکار آن نمی‌شود.

## برنامه‌ریزی ظرفیت

- ظرفیت برنامه‌ریزی objectهای اصلی در سال اول MVP برابر ۱ ترابایت است؛ این عدد سقف محصول یا سهمیهٔ کاربر نیست.
- در مصرف ۷۰٪ هشدار بررسی روند و هزینه و در مصرف ۹۰٪ هشدار فوری افزایش ظرفیت صادر می‌شود.
- backupها و کپی‌های بازیابی جدا از این ۱ ترابایت برآورد و پایش می‌شوند.
- مصرف واقعی، رشد ماهانه، میانگین حجم و تعداد فایل به تفکیک purpose اندازه‌گیری می‌شود تا برآورد پس از شروع پایلوت اصلاح شود.
- رسیدن به آستانه باعث حذف یا کاهش خودکار مدت نگهداری فایل نمی‌شود؛ سیاست حذف همچنان فقط از ADR-0006 پیروی می‌کند.

## آزمون پذیرش

- فایل در مرز دقیق حجم پذیرفته و فایل بزرگ‌تر رد شود.
- ناسازگاری پسوند، MIME و signature رد شود.
- فایل یازدهم در یک ارسال رد شود و خطای قابل‌فهم برگردد.
- فایل آلوده یا اسکن‌نشده قابل‌دریافت نباشد.
- کاربر بدون مجوز نتواند metadata یا URL دسترسی فایل کسب‌وکار دیگر را دریافت کند.
