## شروع PRD-02 — کاتالوگ عمومی و SEO، 2026-09-28

برش عمومی `CAP-CAT-10..12` و بخش عمومی `CAP-CAT-13` در مسیرهای `/fa|en/catalog`،
`/fa|en/catalog/{id}` و `/fa|en/manufacturers/{id}` پیاده شد. فهرست، جست‌وجوی فارسی
نرمال‌شده، فیلترهای عرضه/روش فروش/سفارش‌پذیری، مرتب‌سازی، صفحه‌بندی و دستهٔ انتخابی در URL
می‌مانند. حالت خالی، retry خطای route و نمایش موبایل/دسکتاپ پوشش داده شده‌اند.

feature کاتالوگ schema پاسخ عمومی، کلیدهای `public`، queryOptions مشترک و adapterهای جداگانهٔ
server/browser دارد. RSC با QueryClient جدا داده را می‌گیرد و فقط query عمومی موفق را hydrate
می‌کند؛ مرورگر از BFF هم‌مبدأ می‌خواند. schema عمومی وجود `wholesale` یا
`representative_price_irr` را رد می‌کند تا cache/HTML عمومی نتواند مبلغ را بپذیرد.

صفحهٔ محصول و تولیدکننده canonical/hreflang، metadata و JSON-LD بدون Offer/قیمت دارند؛ sitemap
در محیط indexable، محصول‌های منتشرشده و تولیدکننده‌های آن‌ها را از API عمومی می‌سازد. شمارهٔ تماس،
نشانی دقیق و مدارک وارد UI یا دادهٔ ساختاریافته نمی‌شوند. لینک کاتالوگ به header مشترک اضافه شد.

شاهد برش عمومی: دو جریان واقعی
انگلیسی دسکتاپ و فارسی موبایل با Django و PostgreSQL موقت، جست‌وجوی ی/ک عربی، جزئیات، SEO،
پروفایل تولیدکننده، نبود اطلاعات خصوصی و نبود کلید قیمت را تأیید کردند.

## ادامهٔ PRD-02 — قیمت عمدهٔ کنترل‌شده، 2026-09-29

بخش frontend معیارهای `AC-CAT-28..30` و `AC-CAT-34` تکمیل شد. مرورگر ابتدا از BFF خصوصی، نشست
زنده و Business خرده‌فروش verified را بررسی می‌کند. خواندن فهرست و جزئیات قیمت نیز همان مجوز را
دوباره در BFF بررسی می‌کند و Django مرجع نهایی `can_view_wholesale` باقی می‌ماند. JWT از vault خارج
نمی‌شود. پاسخ قیمت `private, no-store` است و در namespace جدا با scope شناسهٔ Business قرار می‌گیرد؛
هیچ قیمت یا مجوزی در RSC، HTML، JSON-LD یا کلید عمومی hydrate نمی‌شود.

کارت برای بازیگر مجاز قیمت نماینده را با «از» و صفحهٔ جزئیات جدول کامل پله‌ها و قیمت مؤثر هر SKU
را نشان می‌دهد. URL بازهٔ قیمت را به تومان نگه می‌دارد و BFF در مرز backend آن را دقیقاً به ریال
تبدیل می‌کند. مرتب‌سازی قیمت و فیلتر بازه فقط پس از مجوز زنده نمایش داده می‌شوند. خرید یا افزودن
به سبد در این برش وجود ندارد و مجوز مستقل controlled access برای PRD-04 حفظ شده است.

شاهد فعلی: ۱۶۶ تست واحد/کامپوننت، typecheck بدون deprecated و lint/architecture موفق؛ تست واقعی
خرده‌فروش verified ورود، نبود قیمت در HTML اولیه، نمایش کارت و جدول، فیلتر تومان→ریال و حذف قیمت
پس از logout را تأیید می‌کند. جریان‌های عمومی انگلیسی و فارسی نیز همچنان نبود قیمت را می‌سنجند.
ادامهٔ PRD-02 شامل پنل‌های تولیدکننده/اپراتور برای `CAP-CAT-01..09` است؛ این برش به‌تنهایی
PRD-02 را کامل نمی‌کند.

## برش نشست و حساب شخصی PRD-01 — 2026-09-25

- ورود فارسی/انگلیسی، صفحهٔ حساب شخصی محافظت‌شده، guard زندهٔ Django و logout اجرا شدند.
- NextAuth cookie فقط شناسهٔ opaque نگه می‌دارد؛ JWTهای Django در vault رمز‌شدهٔ PostgreSQL
  هستند. تصمیم refresh میان replicaها در [قرارداد نشست](web-sessions.md) ثبت شد.
- قفل advisory و marker پایدار `refreshing` قبل از درخواست، replay تصادفی را مسدود می‌کنند.
  Logout نامطمئن دادهٔ خصوصی را پاک و دسترسی را می‌بندد، ولی موفقیت سرور را ادعا نمی‌کند.
- صفحهٔ خصوصی DTO شخص را در HTML/RSC نمی‌گذارد؛ query فعال باید دوباره از BFF مجوز بگیرد.
  تغییر هویت/خروج cache را پاک می‌کند و پیام بدون هویت برای تب‌های دیگر می‌فرستد.
- فرم‌ها تا آماده‌شدن React Hook Form غیرفعال‌اند و fallback ارسال POST است. شادکن
  Card/Field/Input/Button/Alert/Spinner و catalog فارسی/انگلیسی استفاده شده‌اند.
- پایگاه محلی مستقل `marketplace_web` و schema آن آماده شد؛ secretهای محلی فقط در env
  خارج از Git نگهداری می‌شوند. اجرا در استقرار تازه مستلزم env و `pnpm session:migrate` است.

شاهد فعلی: ۱۲۰ تست Vitest، typecheck، lint/architecture و build موفق؛ ۳ آزمون یکپارچهٔ
حساب در هرکدام از Chrome دسکتاپ، Chrome موبایل و Playwright WebKit موفق شدند. هر اجرا
Django واقعی، PostgreSQL موقت و دو پردازش مستقل فرانت‌اند دارد. تست‌ها CSRF، logout،
Back/Forward، تب دوم، پاسخ دیررس، تغییر A→B، انقضای Django، تعلیق و refresh هم‌زمان را
پوشش می‌دهند. ایراد دریافت پیام خروج توسط خود تب با تست رگرسیون رفع شد.

محدودیت شاهد: مرورگرهای اجراشده سند خصوصی no-store را وارد BFCache بومی نکردند؛
history واقعی و چرخهٔ persisted pagehide/pageshow جداگانه تست شدند. این نتیجه ادعای
restore بومی نیست. دانلود Firefox در محیط محلی متوقف ماند و اجرای آن تأیید نشده است؛
remote CI، Safari واقعی و staging گیت انتشارند. این برش کل PRD-01 را تمام نمی‌کند؛ ادامه
با تأیید ایمیل/بازیابی حساب و سپس onboarding است. مجوز کسب‌وکار/عملیات همراه مصرف واقعی
خودش باید در Django و BFF آزموده شود.

رگرسیون نهایی: ۲۶ تست مرورگر عمومی و ۲ تست ثبت‌نام واقعی روی standalone موفق شدند؛
مجموع آزمون‌های مرورگری اجراشده در این checkpoint برابر ۳۷ است. نصب frozen/strict-peer،
format:check و diff whitespace check نیز موفق بودند. CI برای Chrome موبایل و WebKit
به‌روزرسانی شد، ولی نتیجهٔ remote CI هنوز مشاهده نشده است.

۱۱ تست هدفمند `tests/test_auth.py` بک‌اند موفق شدند و پس از آزمون‌ها هیچ دیتابیس
`test_frontend_` باقی نماند. داده‌های اپلیکیشن بک‌اند پورت 8000 در این آزمون‌ها تغییر نکردند.
