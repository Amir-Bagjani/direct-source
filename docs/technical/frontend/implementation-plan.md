# ادامهٔ مرحله‌ای فرانت‌اند

## قرارداد انجام کار

مرجع رفتار، ۸ PRD موجود است؛ PRD موازی و تکراری ایجاد نمی‌شود.
هر برش: خواندن PRD/requirement/API، ثبت معیار پذیرش UI، اجرا، تست مرتبط و به‌روزرسانی وضعیت.
هیچ PRD زیر با آماده‌شدن base تکمیل‌شده محسوب نمی‌شود.

## ترتیب پس از base

1. PRD-01: تصمیم و تست امنیت NextAuth/BFF/refresh هم‌زمان؛ سپس ورود و onboarding.
2. PRD-02: کاتالوگ عمومی، SEO محصول/تولیدکننده، queryOptions و hydration، پنل تولیدکننده.
3. PRD-04 و بخش خرید PRD-03: سبد، quote، تغییر قیمت، checkout idempotent، تصمیم سفارش.
4. PRD-03 و PRD-05: حمل، تحویل، پرداخت و صورتحساب، برگشت و تسویه مطابق زبان محصول.
5. PRD-06 و PRD-07: مغایرت/پشتیبانی، فایل خصوصی، امتیاز و نظر.
6. PRD-08: پنل عملیات، دسترسی‌ها و dashboard؛ سپس pilot و اندازه‌گیری performance.

- فارسی/انگلیسی، موبایل/دسکتاپ، keyboard، حالت‌های loading/error/empty بررسی شوند.

- full build در checkpoint فاز/CI/release؛ برای تسک معمول تست و typecheck مرتبط کافی است.
- staging، observability، بار هم‌زمان، provider و پرداخت/ارسال واقعی با base تأیید نشده‌اند.

## شروع PRD-01 — ثبت‌نام عمومی، 2026-09-24

پیش‌نیاز عمومی `CAP-ACC-01` در `/fa/register` و `/en/register` پیاده شد: فرم shadcn،
React Hook Form/Zod، mutation با TanStack Query و BFF ثابت ثبت‌نام. این برش نشست نمی‌سازد،
Business نمی‌سازد و هیچ مسیر خصوصی را فعال نمی‌کند. تکمیل `AC-ACC-01` در وب به ورود امن
وابسته است؛ گیت session/guard/logout بالا همچنان باز است.

- BFF: origin پیکربندی‌شده، JSON محدود به 8 KiB، schema ورودی/خروجی، no-store، timeout،
  بدون redirect/retry و بدون ارسال cookie یا هدرهای browser به Django.
- موفقیت فقط `{created: true}` است؛ خطاهای backend به کدهای امن و copy محلی تبدیل می‌شوند.
  نتیجهٔ مبهم شبکه موفقیت محسوب نمی‌شود و درخواست خودکار تکرار نمی‌شود.
- رمز در variables کش mutation قرار نمی‌گیرد؛ فرم بعد از موفقیت پاک می‌شود.
- صفحه‌های قوانین و حریم خصوصی با درخواست صریح کاربر از قواعد موجود محصول نوشته شدند؛
  هر دو زبان، مسیر عمومی و لینک برگهٔ جدید از فرم دارند. نسخهٔ پذیرش همچنان در Django ثبت
  می‌شود؛ متن با شناسهٔ سیاست موجود `2026-09-07` مستند شده است.
- تست مرورگر با Django واقعی و PostgreSQL موقت، ثبت موفق، ورود API، نبود Business و رد
  ثبت تکراری را اثبات می‌کند. این تست شاهد login/logout وب و `AC-ACC-31` نیست.

ادامه: تصمیم ذخیرهٔ session و single-flight قابل‌اتکا میان replicaها، سپس Credentials
NextAuth، guard و `AC-ACC-31`؛ پس از آن onboarding کسب‌وکار. ثبت‌نام عمومی جای این گیت نیست.

## برش نشست و حساب شخصی PRD-01 — 2026-09-25

- ورود فارسی/انگلیسی، صفحهٔ حساب شخصی محافظت‌شده، guard زندهٔ Django و logout اجرا شدند.
- NextAuth cookie فقط شناسهٔ opaque نگه می‌دارد؛ JWTهای Django در vault رمز‌شدهٔ PostgreSQL
  هستند. تصمیم refresh میان replicaها در [قرارداد نشست](web-sessions.md) ثبت شد.
- قفل advisory و marker پایدار `refreshing` قبل از درخواست، replay تصادفی را مسدود می‌کنند.
  Logout نامطمئن دادهٔ خصوصی را پاک و دسترسی را می‌بندد، ولی موفقیت سرور را ادعا نمی‌کند.
- صفحهٔ خصوصی DTO شخص را در HTML/RSC نمی‌گذارد؛ query فعال باید دوباره از BFF مجوز بگیرد.
  تغییر هویت/خروج cache را پاک می‌کند و پیام بدون هویت برای تب‌های دیگر می‌فرستد.
- فرم‌ها تا آماده‌شدن React Hook Form غیرفعال‌اند و fallback ارسال POST است. شادکن
  Card/Field/Input/Button/Alert/Spinner و catalog فارسی/انگلیسی استفاده شده‌اند.
- پایگاه محلی مستقل `marketplace_web` و schema آن آماده شد؛ secretهای محلی فقط در env
  خارج از Git نگهداری می‌شوند. اجرا در استقرار تازه مستلزم env و `pnpm session:migrate` است.

شاهد فعلی: ۱۲۰ تست Vitest، typecheck، lint/architecture و build موفق؛ ۳ آزمون یکپارچهٔ
حساب در هرکدام از Chrome دسکتاپ، Chrome موبایل و Playwright WebKit موفق شدند. هر اجرا
Django واقعی، PostgreSQL موقت و دو پردازش مستقل فرانت‌اند دارد. تست‌ها CSRF، logout،
Back/Forward، تب دوم، پاسخ دیررس، تغییر A→B، انقضای Django، تعلیق و refresh هم‌زمان را
پوشش می‌دهند. ایراد دریافت پیام خروج توسط خود تب با تست رگرسیون رفع شد.

محدودیت شاهد: مرورگرهای اجراشده سند خصوصی no-store را وارد BFCache بومی نکردند؛
history واقعی و چرخهٔ persisted pagehide/pageshow جداگانه تست شدند. این نتیجه ادعای
restore بومی نیست. دانلود Firefox در محیط محلی متوقف ماند و اجرای آن تأیید نشده است؛
remote CI، Safari واقعی و staging گیت انتشارند. این برش کل PRD-01 را تمام نمی‌کند؛ ادامه
با تأیید ایمیل/بازیابی حساب و سپس onboarding است. مجوز کسب‌وکار/عملیات همراه مصرف واقعی
خودش باید در Django و BFF آزموده شود.

رگرسیون نهایی: ۲۶ تست مرورگر عمومی و ۲ تست ثبت‌نام واقعی روی standalone موفق شدند؛
مجموع آزمون‌های مرورگری اجراشده در این checkpoint برابر ۳۷ است. نصب frozen/strict-peer،
format:check و diff whitespace check نیز موفق بودند. CI برای Chrome موبایل و WebKit
به‌روزرسانی شد، ولی نتیجهٔ remote CI هنوز مشاهده نشده است.

۱۱ تست هدفمند `tests/test_auth.py` بک‌اند موفق شدند و پس از آزمون‌ها هیچ دیتابیس
`test_frontend_` باقی نماند. داده‌های اپلیکیشن بک‌اند پورت 8000 در این آزمون‌ها تغییر نکردند.


## برش تأیید ایمیل و بازیابی PRD-01 — 2026-09-26

تنظیمات ثبت/تغییر/حذف ایمیل با رمز فعلی، ارسال دوبارهٔ تأیید، درخواست بازیابی و مصرف صریح
لینک در فارسی و انگلیسی پیاده شدند. UI از shadcn موجود و mutationهای TanStack Query استفاده
می‌کند؛ وابستگی تازه، cookie چالش یا cache توکن اضافه نشد. قرارداد fragment لینک و نیاز به
راه‌اندازی worker با نسخهٔ تازه در `../api/auth-and-trust.md` ثبت است.

- build تولیدی، typecheck بدون deprecated، lint/architecture و format:check موفق.
- ۱۲۶ تست واحد/کامپوننت موفق؛ تست چهارم BFF برای حذف ایمیل سپس جداگانه پاس شد
  (مجموع فعلی ۱۲۷ تست). ۱۱ تست هدفمند auth بک‌اند نیز موفق بودند.
- جریان واقعی ایمیل/بازیابی با Django، PostgreSQL موقت و worker واقعی در Chrome فارسی
  دسکتاپ و انگلیسی موبایل موفق؛ SMTP این fixture درون حافظه است و ایمیل بیرونی نمی‌فرستد.
- رمز فعلی نادرست، ایمیل تأییدنشده، تعویض لینک، GET/reload بدون مصرف، بازیابی، رد cookie و
  رمز قبلی و خروج تب دیگر آزموده شدند. محدودیت واقعی پنج درخواست ایمیل در ساعت تغییر نکرد.
- سه تست رگرسیون نشست، history/تب دیگر و refresh میان دو پردازش نیز موفق بودند.
- اجرای نخست به علت خاموش‌بودن PostgreSQL شروع نشد؛ پس از راه‌اندازی سرویس پاس شد.
  تست واقعی نبود Content-Type در adapter فرم را آشکار کرد و با اصلاح آن پاس شد. انتظار
  تأیید در تب headless با بازهٔ واقعی polling هماهنگ شد؛ منطق مجوزدهی ضعیف نشد.

این برش به `AC-ACC-25..27` مربوط است؛ ادامهٔ PRD-01 onboarding کسب‌وکار است. محدودیت‌های
انتشار BFCache بومی، Firefox/Safari واقعی و remote CI همچنان طبق گزارش نشست باقی‌اند.


رگرسیون پایان این برش: ۲۶ تست عمومی/ثبت‌نام UI نیز روی standalone پاس شدند؛ مجموع
آزمون‌های مرورگری این اجرا ۳۱ است (۲ بازیابی، ۳ نشست، ۲۶ عمومی). بررسی Ruff فایل‌های
تغییریافته، whitespace diff و حذف همهٔ دیتابیس‌های موقت `test_frontend_` موفق بودند.
نسخهٔ اجراشدهٔ worker محلی پورت 8000 در این برش بازسازی نشده است؛ اجرای لینک‌های جدید
در آن محیط مستلزم استقرار/راه‌اندازی همان worker با کد تازه است.
