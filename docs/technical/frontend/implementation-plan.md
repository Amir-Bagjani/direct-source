# ادامهٔ مرحله‌ای فرانت‌اند

## قرارداد انجام کار

مرجع رفتار، ۸ PRD موجود است؛ PRD موازی و تکراری ایجاد نمی‌شود.
هر برش: خواندن PRD/requirement/API، ثبت معیار پذیرش UI، اجرا، تست مرتبط و به‌روزرسانی وضعیت.
هیچ PRD زیر با آماده‌شدن base تکمیل‌شده محسوب نمی‌شود.

## ترتیب پس از base

1. PRD-01: تصمیم و تست امنیت NextAuth/BFF/refresh هم‌زمان؛ سپس ورود و onboarding.
2. PRD-02: کاتالوگ عمومی، SEO محصول/تولیدکننده، queryOptions و hydration، پنل تولیدکننده.
3. PRD-04 و بخش خرید PRD-03: سبد، quote، تغییر قیمت، checkout idempotent، تصمیم سفارش.
4. PRD-03 و PRD-05: حمل، تحویل، پرداخت و صورتحساب، برگشت و تسویه مطابق زبان محصول.
5. PRD-06 و PRD-07: مغایرت/پشتیبانی، فایل خصوصی، امتیاز و نظر.
6. PRD-08: پنل عملیات، دسترسی‌ها و dashboard؛ سپس pilot و اندازه‌گیری performance.

## برش نشست و حساب شخصی PRD-01 — 2026-09-25

- ورود فارسی/انگلیسی، صفحهٔ حساب شخصی محافظت‌شده، guard زندهٔ Django و logout اجرا شدند.
- NextAuth cookie فقط شناسهٔ opaque نگه می‌دارد؛ JWTهای Django در vault رمز‌شدهٔ PostgreSQL
  هستند. تصمیم refresh میان replicaها در [قرارداد نشست](web-sessions.md) ثبت شد.
- قفل advisory و marker پایدار `refreshing` قبل از درخواست، replay تصادفی را مسدود می‌کنند.
  Logout نامطمئن دادهٔ خصوصی را پاک و دسترسی را می‌بندد، ولی موفقیت سرور را ادعا نمی‌کند.
- صفحهٔ خصوصی DTO شخص را در HTML/RSC نمی‌گذارد؛ query فعال باید دوباره از BFF مجوز بگیرد.
  تغییر هویت/خروج cache را پاک می‌کند و پیام بدون هویت برای تب‌های دیگر می‌فرستد.
- فرم‌ها تا آماده‌شدن React Hook Form غیرفعال‌اند و fallback ارسال POST است. شادکن
  Card/Field/Input/Button/Alert/Spinner و catalog فارسی/انگلیسی استفاده شده‌اند.
- پایگاه محلی مستقل `marketplace_web` و schema آن آماده شد؛ secretهای محلی فقط در env
  خارج از Git نگهداری می‌شوند. اجرا در استقرار تازه مستلزم env و `pnpm session:migrate` است.

شاهد فعلی: ۱۲۰ تست Vitest، typecheck، lint/architecture و build موفق؛ ۳ آزمون یکپارچهٔ
حساب در هرکدام از Chrome دسکتاپ، Chrome موبایل و Playwright WebKit موفق شدند. هر اجرا
Django واقعی، PostgreSQL موقت و دو پردازش مستقل فرانت‌اند دارد. تست‌ها CSRF، logout،
Back/Forward، تب دوم، پاسخ دیررس، تغییر A→B، انقضای Django، تعلیق و refresh هم‌زمان را
پوشش می‌دهند. ایراد دریافت پیام خروج توسط خود تب با تست رگرسیون رفع شد.

محدودیت شاهد: مرورگرهای اجراشده سند خصوصی no-store را وارد BFCache بومی نکردند؛
history واقعی و چرخهٔ persisted pagehide/pageshow جداگانه تست شدند. این نتیجه ادعای
restore بومی نیست. دانلود Firefox در محیط محلی متوقف ماند و اجرای آن تأیید نشده است؛
remote CI، Safari واقعی و staging گیت انتشارند. این برش کل PRD-01 را تمام نمی‌کند؛ ادامه
با تأیید ایمیل/بازیابی حساب و سپس onboarding است. مجوز کسب‌وکار/عملیات همراه مصرف واقعی
خودش باید در Django و BFF آزموده شود.

رگرسیون نهایی: ۲۶ تست مرورگر عمومی و ۲ تست ثبت‌نام واقعی روی standalone موفق شدند؛
مجموع آزمون‌های مرورگری اجراشده در این checkpoint برابر ۳۷ است. نصب frozen/strict-peer،
format:check و diff whitespace check نیز موفق بودند. CI برای Chrome موبایل و WebKit
به‌روزرسانی شد، ولی نتیجهٔ remote CI هنوز مشاهده نشده است.

۱۱ تست هدفمند `tests/test_auth.py` بک‌اند موفق شدند و پس از آزمون‌ها هیچ دیتابیس
`test_frontend_` باقی نماند. داده‌های اپلیکیشن بک‌اند پورت 8000 در این آزمون‌ها تغییر نکردند.


## برش تأیید ایمیل و بازیابی PRD-01 — 2026-09-26

تنظیمات ثبت/تغییر/حذف ایمیل با رمز فعلی، ارسال دوبارهٔ تأیید، درخواست بازیابی و مصرف صریح
لینک در فارسی و انگلیسی پیاده شدند. UI از shadcn موجود و mutationهای TanStack Query استفاده
می‌کند؛ وابستگی تازه، cookie چالش یا cache توکن اضافه نشد. قرارداد fragment لینک و نیاز به
راه‌اندازی worker با نسخهٔ تازه در `../api/auth-and-trust.md` ثبت است.

- build تولیدی، typecheck بدون deprecated، lint/architecture و format:check موفق.
- ۱۲۶ تست واحد/کامپوننت موفق؛ تست چهارم BFF برای حذف ایمیل سپس جداگانه پاس شد
  (مجموع فعلی ۱۲۷ تست). ۱۱ تست هدفمند auth بک‌اند نیز موفق بودند.
- جریان واقعی ایمیل/بازیابی با Django، PostgreSQL موقت و worker واقعی در Chrome فارسی
  دسکتاپ و انگلیسی موبایل موفق؛ SMTP این fixture درون حافظه است و ایمیل بیرونی نمی‌فرستد.
- رمز فعلی نادرست، ایمیل تأییدنشده، تعویض لینک، GET/reload بدون مصرف، بازیابی، رد cookie و
  رمز قبلی و خروج تب دیگر آزموده شدند. محدودیت واقعی پنج درخواست ایمیل در ساعت تغییر نکرد.
- سه تست رگرسیون نشست، history/تب دیگر و refresh میان دو پردازش نیز موفق بودند.
- اجرای نخست به علت خاموش‌بودن PostgreSQL شروع نشد؛ پس از راه‌اندازی سرویس پاس شد.
  تست واقعی نبود Content-Type در adapter فرم را آشکار کرد و با اصلاح آن پاس شد. انتظار
  تأیید در تب headless با بازهٔ واقعی polling هماهنگ شد؛ منطق مجوزدهی ضعیف نشد.

این برش به `AC-ACC-25..27` مربوط است؛ ادامهٔ PRD-01 onboarding کسب‌وکار است. محدودیت‌های
انتشار BFCache بومی، Firefox/Safari واقعی و remote CI همچنان طبق گزارش نشست باقی‌اند.


رگرسیون پایان این برش: ۲۶ تست عمومی/ثبت‌نام UI نیز روی standalone پاس شدند؛ مجموع
آزمون‌های مرورگری این اجرا ۳۱ است (۲ بازیابی، ۳ نشست، ۲۶ عمومی). بررسی Ruff فایل‌های
تغییریافته، whitespace diff و حذف همهٔ دیتابیس‌های موقت `test_frontend_` موفق بودند.
نسخهٔ اجراشدهٔ worker محلی پورت 8000 در این برش بازسازی نشده است؛ اجرای لینک‌های جدید

## برش ساخت پروفایل اولیهٔ کسب‌وکار — 2026-09-26

بخش کسب‌وکار در صفحهٔ حساب، ساخت پروفایل تولیدکننده/خرده‌فروش و نمایش پروفایل مالک را
در فارسی و انگلیسی ارائه می‌کند (`AC-ACC-04..05`). فیلدها مطابق API موجودند؛ وضعیت اولیه
پیش‌نویس است و هیچ مجوز معامله از ورود یا ساخت پروفایل استنتاج نمی‌شود. NativeSelect و
Textarea رسمی shadcn در کنار Field، Input، Card، Alert و Button موجود استفاده شدند.

BFF همان نشست و transport سمت سرور را مصرف می‌کند؛ مالک و وضعیت از مرورگر پذیرفته
نمی‌شوند. کلید Query به شناسهٔ کاربر محدود است و هنگام خروج/تعویض نشست پاک می‌شود.
ساخت خودکار تکرار نمی‌شود؛ پاسخ نامطمئن با خواندن پروفایل قابل بررسی است. پاسخ mutation
فقط تأیید ساخت دارد تا پاسخ دیررس نتواند پروفایل خصوصی را دوباره در cache بنویسد.

شواهد این برش: ۱۳۹ تست واحد/کامپوننت، ۱۲ تست هدفمند business بک‌اند، چهار سناریوی واقعی
کسب‌وکار (فارسی/انگلیسی × موبایل/دسکتاپ) و سه تست رگرسیون نشست پاس شدند. Typecheck،
lint/architecture/discovery، format:check و build تولیدی این checkpoint نیز موفق بودند.
تست کسب‌وکار، قطع پاسخ پس از ثبت موفق، جلوگیری از ساخت دوم، جداسازی مالکیت دو کاربر،
خروج و Back را پوشش می‌دهد. اجرای تست‌های کسب‌وکار به CI افزوده شد؛ remote CI تأیید نشده.

CAP-ACC-02 و PRD-01 هنوز کامل نیستند. گام بعد قرارداد و اجرای ویرایش پیش‌نویس و لوگو
است (API فعلی ندارد)، سپس مدارک، ارسال برای بررسی و تصمیم اپراتور. محدودیت‌های انتشار
نشست وب و BFCache بومی همچنان برقرارند.

رگرسیون نهایی ایمیل/بازیابی فارسی با Django و worker واقعی نیز پاس شد؛ مجموع این برش
۸ آزمون مرورگری موفق است (۴ کسب‌وکار، ۳ نشست، ۱ بازیابی). اجرای قبلی بازیابی با قطع
جلسه نتیجهٔ قابل‌مشاهده نداشت؛ اجرای مجدد با موفقیت تمام شد.


## تکمیل ویرایش، لوگو و تأیید کسب‌وکار — 2026-09-26

در همان account محافظت‌شده، ویرایش پروفایل/لوگو، ثبت مستقل هویت و فعالیت، ارسال مشترک،
صف اپراتور، پذیرش مسئولیت، تصمیم مستدل هر بخش، اصلاح و بازگشایی رد اجرا شدند. در پیش‌نویس
نوع و مالک تغییر نمی‌کنند؛ پس از ارسال فقط پروفایلِ فعالیت برگشتی قابل‌ویرایش است. تأیید
هر دو بخش وضعیت verified می‌سازد و controlled_access را فعال نمی‌کند. UI بازنگری اطلاعات
پس از تأیید، دسترسی کنترل‌شده و تعلیق/بازگردانی همچنان ادامهٔ PRD-01 هستند.

زیرساخت موجود استفاده شد: shadcn Input/Checkbox/NativeSelect/Textarea/Field/Card، نشست و
BFF موجود، transport مشترک Django و کلیدهای accounts. فایل از مسیر هم‌مبدأ با مجوز زنده،
no-store، nosniff و sandbox خوانده می‌شود؛ URL ذخیره‌سازی یا JWT منتشر نمی‌شود. نسخهٔ رضایت
از backend دریافت و اسکن واقعی ClamAV برای مدارک/لوگو لازم است. ورودی تاریخ تولد شمسی
با Intl و بدون وابستگی تازه به تاریخ بدون ساعت میلادی تبدیل می‌شود؛ نوروز و کبیسه تست دارند.

تغییر DB: migrations accounts/0004 و operations/0011؛ OpenAPI و typeهای فرانت بازتولید شدند.
این migrationها باید پیش از سرویس‌دهی نسخهٔ تازه روی دیتابیس مقصد اجرا شوند؛ تست‌ها فقط
دیتابیس موقت خود را migrate کردند و دادهٔ backend پورت 8000 را تغییر ندادند.

شواهد: ۱۴۹ تست واحد/کامپوننت فرانت، ۲۳ تست هدفمند backend شامل business/onboarding/files/
revisions، typecheck، lint و architecture/discovery، Ruff، mypy فایل‌های backend تغییرکرده،
بررسی migration و build checkpoint موفق. جریان کامل با Django/PostgreSQL/ClamAV واقعی و
مخزن موقت در فارسی دسکتاپ و انگلیسی موبایل پاس شد: ویرایش/لوگو، مدارک، اصلاح، رد، بازگشایی،
تأیید، رد دسترسی دیگران و ابطال دسترسی اپراتور پس از لغو نقش. خطای نخست E2E از locator وابسته
به input حذف‌شده پس از upload بود؛ locator به label پایدار اصلاح شد، رفتار محصول تغییر نکرد.

CI سرویس ClamAV و هر دو اجرای onboarding را دارد؛ اجرای remote CI و گیت‌های انتشار
BFCache بومی/Safari واقعی همچنان تأیید نشده‌اند. مخزن موقت E2E جایگزین تأیید استقرار S3 نیست.

رگرسیون نهایی — 2026-09-27: سه تست نشست واقعی و ۲۶ تست عمومی/ثبت‌نام UI روی
standalone در دسکتاپ/موبایل پاس شدند. نتیجهٔ ثبت‌شدهٔ اجرای کسب‌وکار نیز passed بود؛
پس از ادامهٔ جلسه، خروجی process آن دیگر قابل بازیابی نبود و شاهد آن `.last-run.json` است.
بررسی نهایی whitespace diff موفق بود؛ با عبور بررسی‌ها این برش بسته شد.


## checkpoint تکمیل PRD-01 — 2026-09-28

بازنگری کسب‌وکار تأییدشده، لوگوی اتمیک، صف و تصمیم بخش‌ها، نقش اپراتور، دسترسی کنترل‌شده،
پیشنهاد/فعال‌سازی/رد/بازگردانی تعلیق User و Business، مدارک تعلیق، تعیین تکلیف سفارش‌های
موجود و تداوم محدود سفارش/پشتیبانی در account پیاده شدند. کاربر عادی دادهٔ عملیات را
نمی‌گیرد؛ اپراتور فقط پروندهٔ واگذارشده را می‌بیند و تصمیم نهایی حساس فقط برای مالک سامانه است.

نمای خصوصی با TanStack Query و کلید accounts موجود، BFF ثابت، schemaهای Zod و mutationهای
بدون retry ساخته شد. فرمان‌های حساس و پاسخ تیکت idempotent هستند. خطای بازخوانی مجوز، دادهٔ
قبلی پرونده را فوراً از UI پنهان می‌کند. هیچ dependency، provider تم یا UI kit تازه اضافه نشد.

Migration `operations/0012` برای purpose مدارک تعلیق روی دیتابیس محلی اعمال شد؛ imageهای
web/worker/beat بازسازی و سرویس پورت 8000 سالم شدند. OpenAPI و typeهای فرانت بازتولید شدند.
شواهد نهایی: ۱۵۸ تست فرانت، ۲۸۶ تست کامل backend، Ruff، mypy، migration check، typecheck،
lint/architecture، format و build تولیدی موفق. جریان کامل با PostgreSQL/ClamAV و ذخیره‌سازی
موقت در فارسی دسکتاپ و انگلیسی موبایل روی build تولیدی پاس شد. سه سناریوی نشست تولیدی
در فارسی/انگلیسی و دو پردازش مستقل نیز بدون رگرسیون پاس شدند.

PRD-01 از نظر پیاده‌سازی محصول بسته است. گام محصول بعدی PRD-02 است. remote CI، مرورگرهای
بومی Safari/Firefox، BFCache بومی و S3 مقصد همچنان شواهد انتشارند و در گزارش نشست/زیرساخت
پیگیری می‌شوند.
